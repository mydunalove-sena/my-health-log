# My Health Log — 세브란스 코디네이터 1차 문의 자료

## 1. 문의 목적

이번 문의의 목적은 **환자를 바로 소개받거나 병원을 통해 정식 테스트를 진행해 달라고 요청하는 것**이 아니다.

먼저 다음을 가볍게 확인한다.

> 개인적으로 건강기록이 필요해서 만든 앱을 직접 사용하고 있는데, 다른 신장이식 환자나 투석환자에게도 실제로 사용할 만한지 소수 사용자의 사용성 피드백을 받아보고 싶습니다. 이런 확인을 해보려면 어떤 방식으로 접근하는 것이 적절한지 의견을 듣고 싶습니다.

핵심은 **방법에 대한 조언을 먼저 구하는 것**이다.

## 2. 앱 한 줄 설명

> My Health Log는 사용자가 직접 건강기록, 검사결과, 복약, 필요 시 복용약(PRN), 증상, 운동기록 등을 기록하고 과거 이력을 확인할 수 있도록 만든 Android 개인 건강기록 앱입니다.

## 3. 왜 만들었는가

앱을 만든 시작점은 두 가지다.

1. 실제 개인 건강관리에 사용할 기록 도구가 필요했다.
2. QA 포트폴리오에서 요구사항 정의부터 구현, 테스트, Regression, 실제 Android 기기 검증까지 진행하는 개인 프로젝트를 만들고 싶었다.

판매나 사업화를 목적으로 시작한 앱은 아니다.

## 4. 현재 상태

현재는 주요 기능 개발과 QA를 일단 마치고 직접 실사용하는 단계다.

현재 문서 기준:

- 앱 코드 기준: `3.6.0+12`
- Android 개인 건강기록 앱
- 로컬 저장 중심
- 건강기록 / 검사결과 / 복약 / PRN / 증상 / 운동 / 통계 / Backup·Restore 기능 포함
- 신장이식, 투석 등 관리 유형별 검사 입력 편의를 고려한 구조 포함

현재 기능이 구현되어 있다는 것과 실제 해당 환자군에게 검증되었다는 것은 구분한다.

현재 검증 범위:

| 대상 | 상태 |
|---|---|
| 신장이식 | 본인 실사용 |
| 투석 | 1차 사용성 검증 후보 |
| 간이식 | 기능적으로 고려됨 / 실제 사용자 검증 전 |
| 폐이식 | 기능적으로 고려됨 / 실제 사용자 검증 전 |
| 췌장이식 | 기능적으로 고려됨 / 실제 사용자 검증 전 |

## 5. 확인하고 싶은 것

확인하려는 것은 의료 효과가 아니라 **앱 사용성**이다.

예를 들어:

- 별도 설명 없이 사용할 수 있는가
- 실제 필요한 건강 항목을 기록할 수 있는가
- 본인이 관리하는 검사 항목이 있는가
- 복약 기록 방식이 실제 패턴에 맞는가
- PRN 기록이 이해하기 쉬운가
- 증상 기록이 실제 사용에 맞는가
- 과거 기록을 찾기 쉬운가
- 반복 입력이 지나치게 번거롭지 않은가
- 잘못 이해하거나 잘못 입력할 가능성이 있는가
- 필요한데 빠진 기능이 있는가
- 불필요하거나 혼란스러운 기능이 있는가
- 일정 기간 후에도 계속 사용할 만한가

## 6. 확인하지 않는 것

이번 사용성 확인에서는 다음을 검증하거나 주장하지 않는다.

- 앱 사용이 건강 상태를 개선하는지
- 치료 결과를 개선하는지
- 검사 수치 관리에 효과가 있는지
- 약 복용 효과를 높이는지
- 특정 검사 수치가 정상인지 위험한지
- 어떤 약을 얼마나 복용해야 하는지
- 증상과 약 사이의 의학적 원인·효과 관계

My Health Log는 **의학적 판정이 아니라 기록 중심**으로 유지한다.

## 7. 첫 문의에서 하지 않을 요청

첫 문의에서는 다음을 바로 요청하지 않는다.

- 환자 이름이나 연락처 요청
- 특정 환자를 소개해 달라는 요청
- 병원이 참가자를 모집해 달라는 요청
- 병원이 앱을 추천해 달라는 요청
- 병원 공식 프로그램처럼 진행해 달라는 요청
- 병원이 앱의 안전성이나 효과를 보증해 달라는 요청
- APK를 바로 환자에게 배포해 달라는 요청

이러한 사항은 적절한 절차가 있는지 먼저 확인한 뒤 판단한다.

## 8. 코디네이터에게 물어볼 핵심 질문

처음에는 다음 정도만 확인한다.

1. 이런 개인 건강기록 앱의 소규모 사용성 피드백을 받아보려는 접근 자체가 괜찮은지
2. 병원을 통해 무언가를 진행하려면 별도로 확인해야 할 절차가 있는지
3. 병원을 통하지 않고 환자 커뮤니티나 개인 접점으로 진행하는 편이 더 적절한지
4. 환자에게 앱을 설명할 때 특히 주의해야 할 표현이나 오해 가능성이 있는지
5. 실제 환자들이 건강기록 앱에서 자주 어려워하는 부분이나 중요하게 보는 기록이 있는지

모르는 제도나 절차가 있다면 추측하지 않고 담당자의 안내를 따른다.

## 9. 가장 짧은 구두 문의 버전

> 제가 개인적으로 건강기록이 필요해서 Android 앱을 하나 만들어 직접 사용하고 있어요. 건강기록, 검사결과, 복약, 증상 같은 내용을 기록하는 앱인데요. 다른 신장이식 환자나 투석환자분들도 실제로 써볼 만한지 소수 사용자의 불편한 점 정도를 확인해보고 싶습니다. 환자분을 소개해 달라는 뜻은 아니고, 이런 걸 해보려면 어떤 방식으로 접근하는 게 적절한지 먼저 여쭤보고 싶었어요.

## 10. 문자·카카오톡용 짧은 문의 문구

> 안녕하세요. 제가 개인적으로 건강기록이 필요해서 Android 건강기록 앱을 하나 만들어 직접 사용하고 있습니다. 건강기록, 검사결과, 복약, PRN, 증상 등을 기록하는 앱인데, 다른 신장이식 환자나 투석환자에게도 실제로 사용할 만한지 소수의 사용성 피드백을 받아보고 싶다는 생각이 들었습니다.
>
> 처음부터 환자분을 소개해 달라거나 정식 테스트를 부탁드리려는 것은 아니고, 이런 확인을 해보려면 어떤 방식으로 접근하는 것이 적절한지 의견을 여쭤보고 싶습니다. 병원을 통해서는 어려운지, 다른 방법이 적절한지 등 편하게 말씀해주시면 그에 맞춰 판단하려고 합니다.

## 11. 조금 더 설명이 필요할 때 사용할 문구

> 이 앱은 검사값을 정상/위험으로 판정하거나 약 복용량을 추천하는 기능은 없습니다. 제가 직접 입력한 건강정보를 날짜별로 기록하고 과거 기록을 확인하는 용도입니다.
>
> 확인하고 싶은 것도 치료 효과가 아니라, 실제 사용자가 기록하기 편한지, 필요한 항목이 있는지, 헷갈리는 부분이나 잘못 입력할 가능성이 있는지 같은 사용성입니다.
>
> 현재는 신장이식과 투석 사용자 정도로 범위를 좁혀 생각하고 있고, 가능한 방법이 있는지 먼저 조언을 구하려고 합니다.

## 12. 코디네이터 반응별 다음 판단

### A. 병원을 통한 진행은 어렵다고 하는 경우

정상적인 결과로 받아들인다.

다음 대안을 검토한다.

- 개인적으로 아는 환자
- 환자 커뮤니티
- 온라인 커뮤니티에서 자발적 참여 모집이 가능한지 확인
- 병원과 무관한 소규모 지인 사용성 확인

병원이 어렵다고 했다는 이유로 프로젝트 실패로 판단하지 않는다.

### B. 별도 절차나 담당 부서 확인이 필요하다고 하는 경우

해당 절차를 먼저 확인한다.

절차가 확인되기 전에는:

- 병원 이름을 모집에 사용하지 않는다
- 병원이 승인한 것처럼 표현하지 않는다
- 환자 모집을 요청하지 않는다

### C. 소수 사용자에게 개인적으로 의견을 받아보는 정도는 가능하다고 하는 경우

그때 다음 준비물을 완성한다.

- 배포 가능한 APK 기준 확인
- 설치 안내
- 참가자용 앱 설명
- 피드백/관찰 양식
- 개인정보 최소화 기준

### D. 추가 설명 자료를 요청받는 경우

다음 내용을 한 페이지 정도로 정리한다.

- 앱 목적
- 주요 기능
- 기록 중심이라는 점
- 사용성 검증 목적
- 1차 대상
- 수집하려는 피드백
- 하지 않는 의료적 주장
- 개인정보 최소화 방식

## 13. 개인정보 관련 주의

코디네이터에게 문의할 때도 환자의 개인 정보를 요청하지 않는다.

특히 처음부터 다음을 요청하지 않는다.

- 이름
- 전화번호
- 주민등록정보
- 병원 등록번호
- 상세 진단정보
- 검사결과 원본
- 투약내역 원본

사용성 검증이 실제 진행될 경우에도 필요한 최소 정보만 다룬다.

## 14. 병원 또는 코디네이터를 포트폴리오에 표현할 때 주의

실제로 확인되지 않은 내용을 다음처럼 표현하지 않는다.

- "세브란스와 협업"
- "세브란스 검증 완료"
- "병원 공식 테스트"
- "의료진 추천 앱"
- "병원 승인 앱"

실제 사실에 따라 다음 정도로만 기록할 수 있다.

예:

- "사용성 검증 방법을 확인하기 위해 이식 코디네이터에게 진행 방식에 대한 의견을 문의함"
- "병원 경유 모집 가능 여부를 문의했으나 실제 모집은 별도 방식으로 진행함"

실제 답변과 진행 결과가 나온 뒤 표현을 확정한다.

## 15. 첫 문의 전에 필요한 것

첫 문의 자체를 위해서는 완성된 APK 배포 자료나 사용자 설문 전체가 반드시 필요한 것은 아니다.

현재 준비되어 있으면 충분한 것:

- 앱 목적을 한두 문장으로 설명할 수 있음
- 의료 효과 검증이 아니라는 점을 설명할 수 있음
- 1차 대상이 신장이식·투석이라는 점이 정리되어 있음
- 어떤 종류의 피드백을 받고 싶은지 설명할 수 있음

실제 참여자를 모집하거나 APK를 전달하기 전에는 추가 준비가 필요하다.

## 16. 문의 후 기록할 내용

코디네이터에게 실제로 문의한 뒤에는 기억에 의존하지 않고 다음을 기록한다.

- 문의 날짜
- 문의 방식: 대면 / 전화 / 문자 등
- 핵심 문의 내용
- 답변 요약
- 병원 경유 가능 여부
- 확인이 필요한 절차
- 추천받은 다른 방법
- 주의하라고 한 사항
- 다음 행동

개인 식별정보가 포함될 필요는 없다.

## 17. 현재 미확정 사항

현재 다음은 아직 확정하지 않는다.

- 실제 참가자 수
- 사용 기간
- 병원 경유 모집 여부
- 환자 커뮤니티 모집 여부
- 참가자 보상 여부
- 실제 배포 APK
- 피드백 수집 방식
- 병원 내부 절차 필요 여부

확인되지 않은 사항은 실제 답변을 받은 뒤 결정한다.

## 18. 이번 문의의 성공 기준

코디네이터가 앱을 좋게 평가하는 것이 성공 기준이 아니다.

다음 중 하나만 얻어도 첫 문의의 목적은 달성한 것으로 본다.

- 가능한 접근 방법을 알게 됨
- 병원을 통한 진행이 어려운 이유를 알게 됨
- 별도 절차가 필요하다는 것을 알게 됨
- 다른 모집 경로를 추천받음
- 환자 입장에서 주의할 점을 들음
- 현재 계획에서 수정해야 할 부분을 발견함

## 19. 최종 원칙

> 처음에는 허락이나 환자 소개를 요구하는 것이 아니라, 실제 사용자 사용성 검증을 어떤 방식으로 접근하는 것이 적절한지 의견을 구한다.

확인된 답변을 바탕으로 그다음 단계를 결정한다.
